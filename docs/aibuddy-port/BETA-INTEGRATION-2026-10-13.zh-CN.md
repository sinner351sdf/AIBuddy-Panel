- 本轮 beta 截止：`e50abff1fdc05c27efc4f1566661129a63eb6c1e`，比审查时多一个更新页社区入口提交；相对稳定基线共 38 个提交、196 个变更路径，其中 33 个新增路径。
- 采用稳定基线到 beta 的内容差异、分批三方适配，不合并无共同祖先的仓库历史。全部 beta 新增路径均已存在，变化路径不存在仍停留在稳定版原文的文件；这项文件核对不替代行为测试。
- 未推送包含旧凭据历史的本地分支。Antigravity OAuth 继续从环境变量读取。

## 第一批：权限、会话与额度

| 审查项 | 已应用修改 | 行为与原因 |
| --- | --- | --- |
| R1 管理权限越界 | 有额度、有效期、模型白名单或提供商白名单的 Key 禁止访问管理 API；新增进程内桌面管理凭证 | 防止调用方导出凭据或解除自身限制，同时保留桌面桥和面板管理会话 |
| R2 恢复后旧会话仍有效 | JSON / SQL 恢复清除旧 access、refresh 会话；缺失或坏的会话记录也替换内存状态 | 恢复后必须用恢复后的管理员账号重新登录 |
| R3 额度账本失败放行 | SQL / JSON / 用量字段错误向上传播；受额度限制的新请求拒绝准入；禁止覆盖坏账本 | 管理页显示统计不可读取，不能冒充零用量 |
| 备份恢复保护 | JSON 导入前备份、校验配置及账号 JSON；SQL 使用暂存库、SQL 授权器和恢复前快照 | 无效输入在覆盖之前拒绝；禁止导入 SQL 跨库附加或危险 PRAGMA |

兼容边界：**没有任何限制的旧式 API Key 仍兼容上游管理权限**。它们应按管理员凭据保管；给调用方分发 Key 时设置相应限制。面板会话及桌面内部凭证独立授权。

额度仍是软额度：已通过准入的在途请求允许完成，并发可能超过上限；无法取得上游 usage 的请求仍有计量边界。按 Key 独立行存储与原子增量的性能重构留作独立优化，本轮保持现有数据格式。

## 第二批：正确性与部署

- **R4 Codex 配置**：支持 `CODEX_HOME`；区分面板与推理端口；支持 `AGENT2API_PUBLIC_API_URL` 和界面编辑外部网关地址。合并已有 TOML，保留其他项目、模型与自定义配置；首次 `.bak` 不覆盖，后续另存备份。
- **R5 探活**：聊天探活最多读取 64 KiB、等待 10 秒，检查 SSE 正文、推理或工具结果及错误帧；不能只凭 HTTP 200 判成功。网络、429、5xx 等临时失败不会累计成永久禁用；只有连续 HTTP 401 认证失败进入停用计数。已被旧版本停用的账号需人工核对后重新启用。
- 保活模型链同时读取旧数组和 `{models:[...]}` 形态，修复保存后回落默认。
- 补齐 Kuku / Command Code 身份解析和导入兼容。
- 更新默认发布源为 `sinner351sdf/AIBuddy-Panel`，可用 `WORKBUDDY_UPDATE_REPO` 覆盖。
- `scripts/start-local.sh` 每次执行 Cargo 增量构建，避免继续启动旧程序。
- Docker Compose 透传外部网关地址、更新仓库及既有 OAuth 环境变量。

Codex 一键配置修改的是**服务进程所在机器**的配置；浏览器在另一台电脑时不会修改浏览器机器。Docker / 反向代理部署应设置实际可访问的外部网关地址。

## 第三批：beta 服务端能力

| 能力 | 移植范围与定制兼容 |
| --- | --- |
| OfficeAce / 果办 / OfficeClaw | 提供商注册、签名、网页登录和凭据导入、续期、转发、目录/倍率、额度、签到与新人福利；包含 beta 后续错误归类和脱敏修复 |
| 路由与队列 | 顺序优先、负载均衡、会话粘性、失败退避、429 垫底、熔断与候选原因预览；采用最终 beta 行为，不恢复已被上游移除的余额优先策略 |
| 路由回放 | 数据库迁移、请求 route 记录和回放数据；保留 Key 维度结算与审计 |
| SQL 整库备份 | 复用 SQLite Backup API、SQL 校验及恢复前备份；桌面接口单独放到 `/api/backup/sql/export`、`/api/backup/sql/import` |
| JSON 与定时备份 | 保留原 `/api/backup/export`、`/api/backup/import` 契约、远程同步、每天备份与保留数量；定时 `.db` 快照改用同一 SQLite Backup API |
| 多条签到计划 | 时间与提供商范围、去重补签、计划 CRUD、每账号签到明细及筛选清理；保留成长任务，仅在 WorkBuddy 签到范围内触发对应连续任务 |
| 签到归类 | CodeArts 每日福利归入日签；手动全部签到不受定时范围限制 |
| 并发额度 | 集中向账号公开形态注入 `maxConcurrent`，覆盖此前遗漏的提供商，保留 CodeArts 默认语义 |
| 验证码池 | 目标库存、轮询间隔、单轮铸造上限及热更新 |
| Trae / 流内拒绝 | 目录中字符串 JSON 倍率解析；适配器声明与 HTTP 200 流内拒绝处理，包含最终 beta 修复 |

**备份格式互不等同**：JSON 搬运配置和账号，SQL 可包含整库日志，定时 `.db` 是数据库文件快照。SQL 文件路径接口仅接受本机桌面内部授权；网页管理员会话和 API Key 均不能调用它读写服务器任意路径。网页继续使用 JSON 备份。执行恢复前保留现有数据，恢复后重新登录。

## 第五批：资源与依赖维护

- 保留现有通知渠道；自动投递总计最多 64 条待发/在途、4 路并发，满载记录丢弃，不阻塞模型转发。单条投递最多 25 秒；通用 Webhook 的网络错误、429、5xx 最多重试一次，间隔 500ms，其他渠道不自动重发。
- 通知通用 HTTP 发送器只读取有限错误正文（8 KiB）；需要解析业务返回值的公共读取器上限 64 KiB。非法 Webhook secret 不再静默省略。Webhook 接收端应容忍重复投递；队列不持久化，重启可能丢失未完成通知。
- `source-map-js` 更新至 1.2.2；只依赖 shadcn 的 CSS，故原样保留其样式与 MIT 许可，移除未使用 CLI 及相关 MCP/glob 工具依赖链，避免强制降级。
- 两个前端项目最新 `npm audit` 均为 0 个已知漏洞；这不是对所有未来漏洞的保证。
