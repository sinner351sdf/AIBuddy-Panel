# WorkBuddy 单账号积分任务弹窗

日期：2026-10-13。账号池中，WorkBuddy 国内版账号的操作栏新增“任务”。任务中心的全账号成长任务入口继续保留。

## 使用与行为

- 打开弹窗只查询所选账号的任务列表与本地执行状态，不自动报名、领取或执行。
- 表格显示任务名与任务码、当前 / 目标进度、积分和能量奖励，以及待接受、进行中、可领取、已领取、未解锁状态。
- 每行支持接受或达标领奖；“全部接受”只报名当前账号尚未接受、未领取且已解锁的任务。
- “一键完成可自动任务”仅扫描和执行所选账号的可自动任务，复用已有接受、动作执行、回读及领奖流程。未解锁、已领取和没有自动执行器的任务不进入队列。
- 自动执行与任务中心共享同一个全局队列和互斥状态：已有队列在跑时禁用操作，后台重复启动返回 409。关闭弹窗不会停止已经启动的后台队列，可在任务中心查看与停止。
- 任务结束后回读任务列表，并刷新主状态。查询失败保留列表并显示错误，点击“重新查询”恢复；错误状态下禁止用旧数据发起任务操作。

## 接口与兼容性

新增三个受保护的管理接口：

| 接口 | 请求与范围 |
| --- | --- |
| `GET /api/growth-tasks/accounts/{id}` | 单账号列表；返回积分、能量、进度、接受和领奖状态 |
| `POST /api/growth-tasks/accounts/{id}/accept` | `{code}` 接受单项，或 `{all:true}` 接受全部可报名任务 |
| `POST /api/growth-tasks/accounts/{id}/claim` | `{code}`；后端重新读取列表，确认任务属于该账号、已解锁且进度达标后领奖 |

原 `POST /api/growth-tasks/run` 新增可选 `accountId`。提供时只执行对应国内版 WorkBuddy 账号、并发固定为 1；省略时继续原全账号流程和并发参数。

提供商与国内版检查先于上游调用，其他提供商和国际版返回 400；不存在或无凭据的账号返回 404。匿名请求返回 401，受限 Key 返回 403。网页和原生桌面都通过既有 `api_request` 桥接调用，无新增凭据配置。

弹窗使用既有主题和对话框组件，适配宽表格、正文滚动及手机横向滚动。仅为该弹窗提高遮罩与内容层级，避免手机侧栏遮挡；组件库其他对话框的默认层级保持不变。补充英文词条，繁体由现有 OpenCC 流程生成；日语、韩语、葡语新增词条暂按既有规则回落中文。

## 验证

- Rust：468 个测试通过、6 忽略，另 1 条文档示例忽略；包含新增提供商 / 版本边界和任务状态序列化测试。
- 单账号 API 回归：53 项断言，覆盖匿名、受限 Key、管理员、错误账号范围、无凭据、无效参数及原全账号无待办行为。
- 原 HTTP 回归：113 项断言通过；既有账号排序 27 个场景及新任务客户端范围、任务状态、URL 转义与失败传播检查通过。
- 服务端构建、macOS 桌面检查、ui-islands 构建、ui-kit 类型检查及 i18n 检查通过。
- 浏览器使用独立临时数据和虚构任务服务：验证入口条件、任务状态、单项接受、全部接受、领取、单账号执行与完成刷新、查询失败 / 恢复、Esc 关闭、浅色 / 深色和 390px 手机布局。核对模拟服务收到的请求，确认单项与批量动作区分准确、执行只含选中账号。

真实账号的自动执行可能消耗对话额度，界面已提示。开发回归未替用户执行真实任务或领取奖励；实际可用任务和奖励以上游返回为准。
