## 实现范围

| 优先级 | 缺口 | 修复后的行为 |
| --- | --- | --- |
| P1 | HTTP 200 内的业务授权失败被误判为成功 | 授权、资料、续期、额度和目录响应先识别业务错误；区分登录失效、账号受限、额度和其它失败 |
| P1 | 登录返回的安全会话字段丢失 | 保留 accessToken、refreshToken、expiresAt、sgcookie、sid；OAuth 换码必须获得完整令牌并验证资料身份，手动添加也必须通过资料验证，失败不能落为已登录账号 |
| P1 | 安全上下文没有交给 SDK | 优先 sgcookie 初始化；没有 cookie 才走环境初始化。SDK 进程及失败退避按账号、地区、设备和 cookie 隔离；切换上下文时重建进程 |
| P1 | 会话式转发缺少一次续期恢复 | 普通 401 仅在未输出内容且上游允许重放时，续期一次、重发一次；第二次失败进入需要重新登录的状态，后续请求在本地拦截 |
| P1 | 已受限的凭证被重复请求 | 明确账号限制时保存 restricted 状态，推理、目录和额度入口通过会话检查阻止后续出网；不通过重试或账号轮换掩盖该限制 |
| P1 | 刷新异常和迟到响应污染当前会话 | 不完整或身份不一致的续期结果不覆盖旧凭证；瞬时续期失败有 30 秒本地退避。回写比较颁发记录，已删除或重新授权的账号不被旧请求改写；restricted 不被较弱失败降级 |
| P2 | team、route region、timezone 未完整传递 | 保存资料 / 授权返回的 team、route region，以及有效的本机时区，条件式加入推理、续期、目录和额度请求；不补造 team 或 route region |
| P2 | v2 目录业务拒绝被泛化 | 仍只使用 `/api/llm/config/v2`，业务失败保留分类；没有回落 v1，推理路径仍为 `/api/adk/llm/generateContent` |

sgcookie 作为不透明输入保存，保留原始内容，不按 Bearer token 处理。它沿用账号整行加密存储，公开账号响应不包含 sgcookie 或 sid。重新导入不同 accessToken 时清除旧令牌与会话字段，再保存本次提供的字段，避免把旧 refreshToken、cookie 或路由交给新会话。

流式返回前会预读首帧。错误发生在已有内容之后时，只结束当前流并报告错误，不续期或重放该次推理。流结束后记录失效 / 受限状态，防止下一次请求继续使用已拒绝会话。临时续期失败提示等待，不错误地要求重新登录。

回环测试的 8 条分支：

1. 首次 401，续期成功后回复；两次推理、一次续期，保留原 sgcookie。
2. 续期后仍 401；两次推理、一次续期，后续调用不再出网。
3. 明确账号锁定；一次推理、零次续期，后续调用本地拒绝。
4. 聚合模式已有部分内容后遇到 401；一次推理、零次续期。
5. 流式模式已输出部分内容后遇到 401；流中报告错误，零次续期，后续调用本地拒绝。
6. 续期响应缺少必需字段；不覆盖旧凭证，不重发推理，并进入本地退避。
7. 续期响应本身为 NOT_LOGIN；不覆盖旧凭证，后续调用要求重新登录。
8. 续期响应本身为 ACCOUNT_LOCKED；不覆盖旧凭证，后续调用保持受限状态。

额外单元测试验证了公开账号不泄漏 cookie、旧失败不能污染重新登录后的令牌、错误路由字段不能进入请求头、不透明 cookie 不被错误裁剪，以及临时续期失败的退避到期后可以继续处理。
