# 网页登录取消后无法重开的修复

Qoder 网页登录取消后，第二次点击打开没有反应，来自两处未收尾的状态：

1. 网页桥的 `cancelLogin` 只清理 `loginActive`，没有结束 `startLogin` 的 Promise，也没有停止轮询或取消服务端任务。共用登录引擎的 `busy` 只能在该 Promise 结束时释放，因此按钮看似复位，但点击仍被忙碌锁拦截。
2. 关闭添加账号的内层表单只调用 `backToPick`，表单使用 `keepMounted` 保留状态，没有卸载，也没有取消当前登录。再次进入同一提供商时仍处于等待态。

修改内容：

- 每轮网页登录保存独立流程对象，包括任务 state、授权窗口、取消信号和结束信号。
- 取消立即结束该轮等待并释放界面忙碌锁，同时按该轮 state 请求 `/api/session/login/cancel`。
- 关闭授权窗口触发取消；启动响应在取消后晚到时，补取消其任务，不导航到旧授权页。
- 停止旧轮询和手工回调等待，晚到的网络响应不得清除下一轮状态、弹层或窗口。
- 正常成功不发送取消请求；错误或超时清理服务端任务，AutoClaw OAuth 取消保持 `ok:false, canceled:true` 语义。
- 内层表单关闭、Esc 和遮罩退出都通过 `backToPick` 取消当前提供商登录，外层关闭继续按原逻辑收尾。

范围：网页面板的共用登录流程，Qoder 国内与国际版及其他共用设备授权流程受益。桌面原生 IPC 登录实现不变。

验证：

- `node scripts/test-web-login-lifecycle.mjs` 直接执行生产网页桥、登录引擎和内层关闭回调，覆盖显式取消、关闭窗口、关闭内层表单、慢启动、晚到轮询、成功/失败、弹窗拦截及手工 OAuth 覆盖层取消。
- 本地模拟授权页验证“打开 → 取消等待 → 再打开”和“打开 → 关闭表单 → 重进 → 再打开”，均能恢复按钮并发起新一轮，服务端收到对应任务的取消事件。
- 网关构建、前端类型检查及构建、113 项 HTTP 回归、27 项排序回归、余额展示和 WorkBuddy 任务客户端回归通过。

测试没有提交真实 Qoder 授权，也没有添加或修改真实账号。更新网关后需刷新已有浏览器页，使它加载新的网页登录桥。
