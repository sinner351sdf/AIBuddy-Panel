# 账号池拖动排序修复

日期：2026-10-13。针对网页账号池的整组拖动与组内拖动。

## 发现与修复

1. **网页缺少重排桥接。** 原生桌面桥和后端已有 `/api/accounts/reorder`，但网页 `workbuddyDesktop` 没有 `reorderAccounts`。调用方使用可选调用，方法缺失仍会显示保存成功。现在网页通过同一受保护接口提交完整队列；调用方检查方法存在，失败时明确报错。
2. **整组向下落点错位。** 拖动模块的下标排除了被拖组，页面取锚点却未排除，导致第一组向下拖后不变、其他向下移动少一位。提取纯队列换算函数，统一按排除被拖组的可见队列换算，同时保留完整成员。
3. **整组拖动缺少视觉反馈。** 标记加在 `tbody` 上，旧 CSS 只匹配行。修正拖动淡化和首行 / 末行边界提示。
4. **轮询重绘与取消边界。** 拖动期间重新按提供商和账号 ID 定位当前节点；松手使用最新节点和落点。只处理起拖指针，取消、Esc、失焦或视图被锁定时清理状态；点击把手没有实际拖动时不提交排序。

## 验证

- `node scripts/test-account-queue.mjs`：10 个完整队列换算场景、12 个指针生命周期场景、5 个网页桥接场景，共 27 个通过。桥接测试执行完整生成脚本，验证认证头、POST 路径和队列正文，并确认 400 / 403 / 500 错误向上传播。
- 浏览器使用独立临时服务、3 个提供商和 9 个无凭据虚构账号，确认整组上移 / 下移、折叠整组拖到最后、同组首项移到末尾及反向移动、刷新保留顺序、搜索与分页锁定。另检查临时数据库中的实际 priority 顺序，避免只凭成功提示判定。
- ui-islands 构建、服务端构建、i18n 检查、既有 113 项 HTTP 回归通过。
- 当前真实数据每组只有一个账号，组内不存在可以交换的对象，拖动该把手不提交排序。这与组内只允许调整同提供商账号顺序的规则一致。

本次修正补上了此前 3.0.2 审查遗漏的网页桥接衔接；文件和后端路由覆盖核对不能替代完整浏览器交互验证。临时测试未修改真实账号或调用外部提供商。
