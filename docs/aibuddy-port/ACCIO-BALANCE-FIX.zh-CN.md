# Accio 百分比额度显示修复

账号页原先显示绿色「可用 — %」。Accio 查询结果的 `available` 为 null，表示没有积分绝对数；实际周期用量保存在 `wallets[].usedPercent` 和 `balance` 中。账号页只识别 `remainingPercent`，因此没有显示已有的剩余比例。

本次修改：

- 后端返回 `remainingPercent = 100 - usagePercent`，用于现有额度进度条。
- 前端兼容旧快照里的百分比 `balance` / `usedPercent`，无需清理数据库即可显示读数。
- 百分比摘要显示「剩余 N%」，悬停提示包含重置时间；其他单位的余额不能套用百分比换算。
- 上游缺失或返回无效的 `usagePercent` 时报告查询失败，取消原先默认 0 已用的行为。前端缺失比例时显示中性的「无数据」，不冒充 0% 或 100%。
- 保留套餐的 `remainQuota / totalQuota` 原始口径。它与周期剩余百分比不同，不相加，也不把套餐数值当成百分比。

验证：前端构建及类型检查通过；`node scripts/test-accio-balance.mjs` 覆盖 24 个旧快照、零值、未知值、其他提供商和错误场景；后端 Accio 余额测试 3 项通过；已有 HTTP 回归 113 项及排序回归 27 项通过。

本地实际额度查询验证了周期已用 0%、剩余 100% 的展示。查询只读取额度，没有发送模型推理请求。

## 余额自动选择展示方式

余额列按数据自动选择展示方式：有余额或套餐余量时直接显示数值，只有百分比时才显示进度条。移除表头全局开关及对应状态，旧的 `workbuddy-desktop-accounts-balance-bars` 存储值不再影响展示。账号数据与选路规则不变。

- 数值展示只移除「可用」前缀，保留提供商的 credits、积分、token 单位和已有的紧凑格式。WorkBuddy 显示 `7068 积分`，小浣熊显示 `9598 积分`，零余额正确显示 `0 credits`。Accio 按用户选定的格式只显示 `698 credits`，套餐总额 `700` 和周期 `100%` 保留在悬停提示中（该套餐原接口未返回单位，credits 是面板显示偏好）。
- 未读到套餐余量、只有周期百分比的账号才画真实剩余进度条。不为已有余额画虚线占位条，也不把未知数据画成满条或空条。
- CodeArts 的积分明细弹层保留，平铺 Token 额度同样优先显示数量，仅有百分比时回退进度条。查询失败和限额徽章仍按原逻辑显示。
- 套餐总额缺失或为 0 时不计算比例；套餐余量为 0 时正常显示，避免把 0 当成缺失。

验证：前端构建和类型检查、24 项既有余额场景、展示模型 / 实际行渲染 / 单位与紧凑格式 / 旧偏好不生效测试、27 项排序回归及 WorkBuddy 任务客户端回归通过。浏览器验证余额列显示 `698 credits`、`0 credits`、积分与 token 单位，且无全局开关。
