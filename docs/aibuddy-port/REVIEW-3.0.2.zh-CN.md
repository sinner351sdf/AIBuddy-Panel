| --- | --- | --- |

## 兼容性及后续优化

1. **备份恢复更严格。** 已注册环境不再接受缺少管理员的快照；需要使用含有效管理员记录的备份。正常恢复后仍需使用备份中的管理员重新登录。升级前保存完整备份，并在维护窗口操作恢复。
2. **额度仍为软额度。** 并发在途请求可能超额，上游缺少 usage 时仍可能无法完整计量。本次改善错误可见性，不承诺硬额度；按 Key 独立行存储和原子增量可作为后续性能改造。
3. **旧式无限制 Key 仍有管理兼容权限。** 这是保留的既有契约；给调用方分发时应设置额度、有效期或白名单，受限 Key 无管理权限。
4. **通知与翻译的已知边界保留。** 通知队列不持久化、重启可能丢失待发消息；部分上游翻译回落简体中文。这些适合独立优化，不应在版本同步时混入大规模重构。
5. **代码版本与正在运行的进程分别生效。** 本次构建与回归验证针对新代码，未重启既有 3065 服务。源码本机部署需重新运行 `scripts/start-local.sh`；Compose 源码部署需 `docker compose up -d --build`。本次未创建安装包或 GitHub Release。

这是一轮针对上游遗漏、关键衔接和恢复 / 权限 / 额度边界的代码审查与回归验证，不代表所有运行条件下都不存在缺陷。
