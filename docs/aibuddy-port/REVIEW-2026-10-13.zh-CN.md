## 已确认的问题

优先级：P1 为应先处理的权限或认证问题；P2 为正确性、可靠性或特定部署下的功能问题。

### R1 · P1：过期/受限 API Key 仍然拥有管理权限

- 位置：`desktop-tauri/src-tauri/server/src/server/http.rs:863–879`；新增敏感接口注册在同文件 `181–209`。
- 原因：管理接口只校验 Key 是否匹配启用列表，随后直接放行，没有区分管理员凭证与仅用于推理的 Key，也没有执行有效期、额度、模型/提供商限制检查。
- 隔离复现：创建额度 100、已过期的 Key。同一 Key 调 `/v1/chat/completions` 返回 **403**，调用 `/api/backup/export` 返回 **200**；调用自己的 quota PUT，移除有效期和额度限制，也返回 **200**。
- 影响：拿到分发给调用方的受限 Key，就能导出包含账号凭据、其他 Key 和管理员哈希的快照，或者解除自己的限制。并非匿名访问漏洞。通用 Key 可管理的逻辑继承自上游，新增受限 Key 与敏感管理接口后，这种兼容逻辑不再满足权限边界。
- 建议：管理会话/独立管理凭证与推理 Key 分离；至少禁止具有任意限制的 Key 访问管理 API。同步调整桌面桥认证，避免简单封禁所有 Key 后破坏桌面端。回归矩阵覆盖匿名、会话、管理凭证、普通推理 Key、过期/耗尽/白名单 Key。

### R2 · P1：恢复备份缺少会话记录时，旧刷新令牌没有失效

- 位置：`desktop-tauri/src-tauri/server/src/server/access.rs:392–412`；恢复调用点 `api/backup_api.rs:224–226`。
- 原因：`load_refresh_tokens()` 在 `panelTokens` 缺失或 JSON 解析失败时直接返回，保留原来的内存刷新令牌表。这个行为用于启动尚可，但不能承担“恢复后替换认证状态”的语义。
- 隔离复现：导出临时数据库快照，移除 `panelTokens` 后恢复；持恢复前的 refresh token 请求 `/api/panel/refresh`，仍返回 **200** 并签发新会话。
- 影响：快照中已经没有该会话，旧客户端仍可续期；不能仅依赖当前 access token 自然过期。现有恢复响应里的警告不足以覆盖这种情况。
- 建议：恢复成功后统一撤销 access 与 refresh 会话，使用恢复后的管理员凭据重新登录；明确缺失、空表、非法数据的失败语义。恢复前自动备份，并验证管理员与配置结构，避免成功覆盖后无法登录。

### R3 · P2：额度账本损坏会使已经耗尽的 Key 再次通过准入

- 位置：`desktop-tauri/src-tauri/server/src/server/core/key_quota.rs:70–82、99–114、209–214`。
- 原因：SQL 读取失败、非法 JSON、部分非法字段被当成空表/零用量；`read_usage()` 的错误还可能被静默吞掉。后续累计可能用新空表覆盖原账本。
- 隔离复现：虚构 Key 的额度和用量均设为 100，请求先返回 **403**；只将临时库 `keyQuotaUsage` 改成非法 JSON，同一请求变成 **400“缺少 messages 数组”**，管理接口报告已用量 **0**。这说明它已越过额度准入，测试没有实际请求模型。
- 建议：区分“合法新 Key 无记录”和“账本不可读取/损坏”。后者对带额度的 Key 拒绝新请求并返回可诊断错误；允许在途请求完成，并保留明确的记账失败告警。软额度允许在途超额，与故障时解除限制是两件事。

### R4 · P2：分端口部署时，Codex 一键配置写错网关地址

- 位置：`desktop-tauri/src-tauri/server/src/server/api/codex_api.rs:68–91、185–200`；`desktop-tauri/ui-islands/src/islands/keys-page.tsx:942–945`。
- 原因：默认地址使用当前管理面板请求的 Host；前端提交时不传 `baseUrl`。设置 `AGENT2API_PANEL_PORT` 后，面板端口不承载 `/v1/*`。
- 隔离复现：使用两个随机端口启动服务；一键配置生成的 base_url 指向面板端口，该端口 `/v1/models` 返回 **404**，真正网关端口返回 **200**。配置文件仅写入临时目录。
- 建议：提供独立的网关外部地址字段，前端允许确认/编辑；优先复用接入文档的地址解析逻辑。反向代理分域不能只机械替换端口。Docker/远程部署还要明确“一键写入”改的是服务端文件，不是浏览器所在电脑；兼顾 `CODEX_HOME` 和已有配置保留。

### R5 · P2：探活把临时错误累计为永久禁用，且只凭 HTTP 2xx 判定聊天成功

- 位置：`desktop-tauri/src-tauri/server/src/server/core/probe.rs:499–514、717–744`。
- 静态证据：聊天探活只看响应头，2xx 立即成功，不检查 SSE 错误帧。轮询中所有非跳过的失败都累计同一个计数，到阈值后写 `enabled:false`；没有根据 429、网络故障、5xx、认证失效分别处理。被禁用账号不再进入下一轮目标集。
- 影响：临时网络故障连续达到阈值后，即便上游恢复，账号也不会自动恢复；HTTP 200 内含错误可能被报告为成功。默认未启用时不会发生定时禁用。
- 建议：将传输可达、目录可读、推理成功作为不同结果；临时故障采用冷却和恢复探测，只有确证凭据永久失效时才建议停用。对 SSE 读取有时间/字节上限的首个有效结果或错误帧。本项未用真实提供商运行复现。

## 发布与维护优化

1. **自己的发布渠道与代码上游应独立配置。** 当前 `core/update/version.rs:11` 的默认更新仓库仍是 `aimod-cc/agent2api`；`core/update/mod.rs:125–130` 支持 `WORKBUDDY_UPDATE_REPO` 覆盖。未覆盖时，桌面软件检查/下载安装的是上游发布包，安装后会回到没有本项目定制的版本。保留 Git `upstream` 不要求安装器也跟随它。应配置本项目发布仓库并建立自己的版本和 Release 产物；这不是自动修改 Git 分支的功能。
2. **当前备份接口与 beta 同路径、不同契约。** 当前 GET `/api/backup/export` 返回 JSON，POST import 接收快照及 `confirm:true`；beta POST export/import 接收本机 `.sql` 文件路径。不能直接用 beta 文件覆盖，否则远程同步和网页导入会断。应显式区分格式/版本/路由，兼容旧快照；路径型能力应限定本机桌面授权场景。
3. **当前历史与 upstream 没有共同祖先。** 发布分支保留的是干净快照历史，`git merge-base HEAD upstream/main` 无结果。后续按记录的基线计算内容差异、分批移植并记录来源提交；不要直接 `merge --allow-unrelated-histories` 或把有旧凭据历史的本地备份分支推回远端。
4. **启动脚本可能继续运行旧二进制。** `scripts/start-local.sh:7–9` 只在可执行文件不存在时构建。以后修改 Rust 再启动，可能仍用旧程序。可改成每次调用 Cargo 增量构建，或显式区分开发启动与已构建部署启动；重启时也要避免旧进程仍占端口。
5. **Key 用量表的扩展性。** 现在每次结算读改写同一个 JSON 总表；多 Key、高并发下会增加锁竞争。需要规模化时改为按 Key 独立行、原子增量更新。保留软额度语义，明确并发在途超额及缺少上游 usage 的计量边界。
6. **探活与外部通知应有资源上界。** 除 R5 外，可收敛到通用 Webhook，限制队列、并发、响应体和重试次数；当前通知 `send()` 会先把完整远端响应体读入内存，再截断用于错误显示（`core/notify.rs:597–605`）。本次未向通知服务发送请求。

隔离实例使用随机 loopback 端口、虚构 Key、临时数据库和临时 Codex 配置目录；测试结束后退出并清理。不触碰当前 3065 服务及真实账号。既有 `scripts/test-aibuddy-port.py` 本次重跑结果为 **111 项断言通过**。四个新复现说明原回归用例缺少相应边界，不代表原回归失效。本次没有重跑全套 Rust/桌面测试，也没有将历史测试结果充作本次验证。

建议实施顺序：

1. 修复 R1/R2 权限和会话问题，补充受限 Key 的管理接口拒绝测试、恢复后的会话撤销测试。
2. 修复 R3/R4，并补入 beta 中保活配置、账号导入和并发限制这三类小修复；明确本项目更新源。
3. 整合备份内核与恢复语义，保留现有 JSON 兼容和定时备份；完善探活分类与恢复机制。
4. 分批移植路由/回放、OfficeAce、签到调度与前端体验；每批保留本项目定制并进行对应协议、数据库和桌面回归。
5. 更新依赖、构建流程与发布文档。每批独立提交，记录 upstream 来源和有意保留的差异。
