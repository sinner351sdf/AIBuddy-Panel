## AI Elements 界面与附件二次审查（2026-10-16）

按用户要求，以官方现成方案替换助手聊天展示。官方 AI Elements 已开始并入 shadcn/ui，本次采用其当前 Base UI [Chat](https://ui.shadcn.com/docs/ai-elements/base/chat)、[Prompt Input](https://ui.shadcn.com/docs/ai-elements/base/prompt-input)、[Message](https://ui.shadcn.com/docs/ai-elements/base/message)、[Confirmation](https://ui.shadcn.com/docs/ai-elements/base/confirmation) 组合源码；替换演示用 transport，接回现有 Rust 网关和真实 AI SDK hook。没有复制演示里的虚构模型、聊天脚本、Web 搜索或模拟执行行为。提示词正文、开关、已保存模型、工具权限、真实用量归属保持原样。

本轮复查及替换中处理的问题：

- 旧 `toWireMessages` 仅取文本，SDK 文件部分会被丢弃。现在文本附件按原 UTF-8 内容与文件名进入用户消息，图片保留内联 `image_url`，通过本地 HTTP 上游核对实际发送报文；不支持的文件不再被静默忽略。
- 非流式 JSON 返回多个工具调用时缺少 SSE 的 `index`，原适配会合并成一条无效工具调用。现在补齐索引，完整批次验证后才释放，JSON 错误正文也保留可读原因。
- 新版工具步骤默认折叠，失败原因可能藏在内部。失败步骤自动展开；确认卡使用官方 Item / ItemActions 模式，仍要求启用权限并逐次确认。
- 复制入口复用原共享剪贴板兜底，处理非安全上下文、权限拒绝及重试，不因 `navigator.clipboard` 缺失抛出未处理错误。
- 输入框过滤 IME composition Enter，避免中文尚未选字就发送。附件读取支持取消；读取失败、无模型时保留草稿和附件，清除/移除/卸载时回收临时 URL。

新增文件选择、多选、输入区拖放、图片粘贴、文本/图片预览、移除、附件单独发送、回答复制及保留附件的重新生成。图片支持 PNG/JPEG/WebP/GIF，识别能力取决于选择的模型；文本、代码、JSON、CSV、日志支持 UTF-8 和带 BOM 的 UTF-16。限制为 6 个附件、单个 4 MB、合计 8 MB，对话请求 24 MB。PDF、Office、压缩包和其它二进制格式目前明确拒绝，提示先导出文本或图片；没有把“选中文件”表述成“模型已经理解任意文档”。文件只在点击发送后随请求进入所选模型，没有新增外部文件存储。
